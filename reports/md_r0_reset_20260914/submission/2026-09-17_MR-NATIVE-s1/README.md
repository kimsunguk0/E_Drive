# 제출물 — MR-NATIVE-s1 (2026-09-17)

**이 제출의 목적은 교정이다.** 순위를 올리는 것이 1차 목적이 아니라, 우리 V0가 서버를
얼마나 잘 예측하는지와 0.15까지 실제로 얼마가 남았는지를 재는 것이다.

## 1. 무엇을 내는가

| 항목 | 값 |
|---|---|
| 모델 | MotionDrive V2 + MR (matching resolution), C32 |
| 체크포인트 | `MR-NATIVE-s1/ckpt_step20554.pth` |
| 학습 | train 310 scene, 20,554 update (3.93 exposure), seed 1 |
| **V0 (plain)** | **0.191002** |
| **V0 (test-matched 재가중)** | **0.165804** |
| `__flops__` | **729,815,613,824 = 729.8 GFLOPs** (컷오프 7,053의 **10.3%**) |
| Params | 26.56 M |
| 4090 bf16 batch-1 | 24.27–24.52 ms → 시간 페널티 **×1.0** |

**이 모델은 V0(tune 37 scene)·H(29 scene)·hist(9 scene)를 학습하지 않았다.**
그래서 받은 리더보드 점수를 우리 V0와 곧바로 비교할 수 있다. 전체 set으로 학습한
모델을 냈다면 비교할 깨끗한 V0가 없어 교정이 성립하지 않는다.

## 2. 형식

`submission.zip` 안에 `submission.json` 하나. 2026-09-01에 실제로 채점된 제출물과
같은 구조다.

- 최상위 객체, 키 **1,126개** = clip token 1,125개 + 정수 `__flops__`
- 각 clip 값은 `[[x,y] × 6]`, **누적 절대 좌표**(미터, 현재 ego 기준, 0.5초 간격 3.0초까지)
- 모델이 이미 누적 좌표를 내므로 예제 스크립트의 `cumsum`을 **다시 적용하면 안 된다**
  (적용 시 끝점이 3.50배로 부풀어 오른다)

## 3. 검증 — 전항 통과

| 검사 | 결과 |

| clip 집합이 공식 test와 정확히 일치 | 누락 0, 잉여 0 (1,125/1,125) |
| 전부 6×2 | 통과 |

물리 상식 검사: 3초 이동거리 p50 **22.57 m**(max 68.28), 구간속도 max **23.23 m/s**
(83.6 km/h). 2026-09-01 제출물(p50 22.65, max 68.05, 22.78 m/s)과 같은 범위다.

## 4. 규정 적합성

2026-08-31에 실격 판정을 받은 구조는 **goal이 planner의 cross-attention query항으로
들어가는 것**이었다. 이 모델은 그 판정 이후 다시 만든 계보이며 해당 구조가 아니다.

- `DirectTrajectoryPlanner.forward(scene_features, motion_features, predicted_state,
  predicted_history)` — **goal 인자가 없다.** query는 학습된 `waypoint_queries`다.
- goal은 scene encoder를 통해 **공유 scene feature에만** 들어간다.
- 제공되는 수치 ego status를 그래프 어디에서도 쓰지 않는다 (`provided_status_used: false`).

## 5. `__flops__`를 어떻게 쟀는가

주최측 `tools/measure_flops.py`와 **같은 counter**를 썼다 —
`torch.utils.flop_counter.FlopCounterMode`, Global 합, 실제 배포 입력 1회 forward.
전처리는 포함되지 않는다.

주의: 다른 보고서에 있는 torch.profiler 값 **1,119.9 G**는 다른 추정기이며 컷오프
판정 기준이 아니다. 두 값은 일치하지 않는다. 파일에 들어간 것은 **729.8 G**다.

VAD 베이스라인에서 "단일 프레임"은 7회 순차 forward 중 1회였다. 이 모델은 과거 4장을
**하나의 top-level forward 안에서** 소비하므로 그 1회가 곧 clip 전체이고, 그 전체를
셌다. 작게 보이려고 나누지 않았다.

## 6. 업로드

**아직 업로드하지 않았다.** 제출은 팀당 **5회 제한**이고 2026-09-01 `v2a_goal` 1회를
썼으므로 **4회 남았다**(사이트에서 확인 필요).

업로드 후에는 이 점수를 보고 후보를 바꾸지 않는다. 바꾸는 순간 test set이 개발 집합이
된다. 다음 후보는 이 점수를 보기 전에 정해 뒀다 — **전체 set 재학습 모델**이다.

## 7. 이 점수로 무엇을 알게 되는가

- 우리 V0 plain 0.191002 과 test-matched 0.165804 중 **어느 쪽이 서버에 가까운가**.
  2026-09-01에는 재가중 값이 −0.3%로 맞았지만, 그것은 실격된 다른 그래프에서
  0.236 수준에서 측정된 것이다. 우리 그래프·0.17 수준에서도 유지되는지는 미확인이다.
- **0.15까지 남은 실제 거리.** 2026-09-01 기준 1위는 0.130537, 3위는 0.142403이었다.
- 우리 이전 제출 0.236239 대비 실제 개선폭.
