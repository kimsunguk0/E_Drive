## 2. 정의 정정 — 전부 수용

- **`v0` 밴드는 현재 순간 속도가 아니다.** `analyze_length_aux.py`의 `v0 = ell_g[:,0]/DT`는
  **GT 미래 첫 [0,0.5]초 chord 길이 / 0.5**다. 이름을
  `gt_first_interval_progress_speed`로 고쳤다. 이전의 "현재 v0 < 0.5 m/s 131행"은
  **"GT 미래 첫 구간 진행속도 < 0.5 m/s인 131행"**으로 읽어야 한다.
  단, history readout의 상대 8.3% 오차 관측은 별개 경로의 측정이며 이 정정으로 사라지지 않는다.
- **`stop_hold`는 3초 완전정지 라벨이 아니다.** 규칙은 `총 chord ≤ 1.0 m`이고 creep을 포함한다.
  `constant`는 나머지에 배정되지 않은 **기본 label**이지 가속도 0이라는 뜻이 아니다.
- **signed b 감소 + D3 악화만으로 산포 증가를 단정하지 않는다.** 시간 재배치, 방향 변화,
  sample 간 상쇄 모두 가능하다. **가설로만 남긴다.**
- **best = terminal이 개발집합 선택 편향을 없애지 않는다.** 내부 checkpoint를 고른 추가 낙관만
  제거할 뿐, 예산과 recipe를 V0에서 고른 편향은 남는다.

## 3. 요청받은 shape trace (실측, 추정 없음)

`motion_shape_trace.json`. 한 번의 실제 forward에서 hook으로 기록했다.

| 항목 | 값 |
|---|---|
| 현재 이미지 | 432×768 |
| 과거 이미지 | 216×384 (정확히 1/2) |
| backbone 입력 | **`[5,3,216,384]`** — 현재 front를 축소해 과거 4장 앞에 붙인 **한 번의 pass** |
| FPN level | `[5,128,27,48]`, `[5,128,14,24]` |
| local correlation | **2회**, 둘 다 radius 2 → **25 bins**<br>fine `[4,32,27,48]` → `[4,25,27,48]`<br>coarse `[4,32,14,24]` → `[4,25,14,24]` |
| cell stride | half-res 8 px = **현재 이미지 16 px** |
| **탐색 반경** | **±16 half-res px = ±32 현재 px** |
| correlation_fuse | `[4,178,27,48]` → `[4,128,27,48]` |
| **pooling 위치** | **correlation_fuse 이후**에 12×16으로 축소 |
| dt | `[0.1, 0.2, 0.5, 1.0]` s, offsets `[1,2,5,10]` |
| time_embed | `[1,4,2]` → `[1,4,128]` |
| planner 입력 | scene `[1,3072,128]`, motion `[1,192,128]`, state `[1,6]`, history `[1,4,4]` |

**리뷰가 우려한 "correlation 이전의 심한 공간 압축"은 없다.** 12×16 pooling은 correlation
**이후**에 일어난다. 제약은 다른 곳에 있다 — backbone stride와 과거 이미지의 절반 해상도다.

## 4. 탐색창이 실제 이동량을 담는가 — 측정했다

`correlation_coverage.json`. test clip 40개, 정지 지면점 격자(전방 5–60 m × 좌우 ±3 m)를
각 clip의 **실제 calibration과 실제 pose 정렬**로 투영해 t0 대비 과거 프레임의 픽셀 이동량을 쟀다.
중앙 속도 5.98 m/s.

| Δt | 이동량 중앙값 | p90 | 최대 | **탐색창(±16px) 초과 비율** |
|---|---:|---:|---:|---:|
| 0.1 s | **0.74 px** | 6.88 | 28.9 | 3.1% |
| 0.2 s | 1.33 px | 12.6 | 47.8 | 6.8% |
| 0.5 s | 2.91 px | 24.9 | 76.9 | 17.9% |
| **1.0 s** | 5.28 px | 39.2 | 97.7 | **28.1%** |

**양방향 제약이 동시에 있다.**

1. **가까운 쌍은 해상도 한계.** −0.1 s의 중앙 이동량 0.74 px는 cell 하나(8 px)의 **1/11**이다.
   그 해상도에서 cost volume은 작은 속도 차이를 구분할 격자가 없다.
   −0.3/−0.4 s를 추가해도 중앙 이동량은 약 1.9/2.5 px로 여전히 **sub-cell**이다.
2. **먼 쌍은 범위 한계.** −1.0 s에서 표본의 28%가 ±16 px를 벗어난다.

**단정하지 않는 것**: 탐색창을 벗어난다고 분기가 무용한 것은 아니다. coarse level은 픽셀 기준
탐색 범위가 2배이고, feature는 pool·fuse되며, 포화된 cost volume도 단조 단서는 남긴다.
이는 전방 카메라 지면 기하이지 네트워크가 실제로 무엇을 쓰는지의 측정이 아니다.

## 5. 후보 역할 분리 — 수용

`candidate_roles.json`에 기록했다. 기존 EXP를 지우지 않았다.

- **`DEPLOY_FALLBACK` = E1-EXP terminal** (0.225592). 제출 파일 1,125 clip, 4090 실측,
  raw B1 parity, 음성대조, 재현 manifest가 **전부 준비된 상태**.
- **`DEV_BEST` = E1-EXP-LEN-s0 terminal** (0.223644). 지금까지 본 최저 V0이고 seed 1에서
  복제됐다. **배포 산출물은 아직 없다.**

승격하려면: 같은 writer로 제출 파일 생성·SHA 기록 → 새 가중치의 raw B1 입출력 parity →
4090 재측정 → registry 재연결 → **H를 열기 전에 후보 변경 이력 기록**.
inference graph와 6개 입력이 동일하므로 **trainer 계약검사와 FLOPs는 처음부터 다시 하지 않는다.**

−0.0017이 서버 분포에서 유지될지는 미확인이며, **사라질 것이라고도 단정하지 않는다.**
−0.005는 개발 투자 우선순위 기준이지 실제 개선을 무가치하게 만드는 기준이 아니다.

## 6. 다음 대조에 대한 제안 — 결정은 사용자

측정이 지지하는 것은 **프레임 추가보다 matching 정밀도**다. 근거는 §4의 1번이다 —
−0.1 s의 이동량이 이미 cell의 1/11이라, 같은 해상도에서 근접 프레임을 더 넣어도
추가되는 쌍 역시 sub-cell이다.

다만 이는 지면 기하 기반 추론이고, **리뷰가 정한 원칙(한 번에 하나만)** 은 그대로 지킨다.
두 선택지를 그대로 둔다.

- **(A) matching 정밀도 한 변수**: correlation을 더 세밀한 level에서 수행하거나 radius의
  normalized 변위 범위를 보존하며 해상도를 올린다. λ·sampler·증강·decoder·관측 수는 고정.
- **(B) H4 대 H6-NEAR**: 기존 4관측 유지 + [0.3,0.4]초 RGB만 추가, ego-motion 분기에만 사용,
  history supervision은 4시점 유지, 두 arm 모두 λ=0.25.

어느 쪽이든 추가 관측을 mask했을 때 기존 H4와 초기 출력이 동등한지 먼저 검사하고,
nominal dt 계약을 유지한다. H6-LONG은 열어 두되 지금 함께 시작하지 않는다.
