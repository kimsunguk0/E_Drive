## 0. 선행 조건 확인 결과 (§6, §7)

리뷰가 요구한 두 확인을 **config와 실제 런타임 trace 양쪽**에서 했다.

| 확인 | 결과 | 근거 |
|---|---|---|
| correlation descriptor가 아직 32인가 | **예, 32** | `config.correlation_channels=32`; 런타임에 두 level 모두 `descriptor_channels=32` |
| 모든 과거가 t0와만 비교되는가 | **예** | `local_correlation` 호출이 정확히 2회 = pyramid level 2개. 각 호출이 과거 4장을 현재에 대해 배치. 인접 과거 간 edge 없음 |

따라서 MR-W64는 이름만 바꾼 중복 실험이 아니고, MR-ADJ도 성립하는 제안이다.

부수적으로 확인한 사실 하나: `time_embed` 입력은 `[Δt, log Δt]`뿐이다. 지금은 모든 edge가
t0 기준이라 Δt가 endpoint 쌍을 유일하게 지정하지만, MR-ADJ를 넣으면 (0,−0.1)과
(−0.1,−0.2)가 같은 Δt를 갖는다. 리뷰가 지적한 endpoint 정보 추가는 **실제로 필요하다**.

## 3. 4090 실측 (§10.2) — 이전 16.272 ms를 승계하지 않음

MR checkpoint를 같은 컨테이너·같은 조건(batch 1, warm, cudnn deterministic, TF32 off)에서
새로 쟀다. `reports/md_r0_reset_20260914/rtx4090_mr_forward_cost.json`

| | E1-EXP | **MR-NATIVE** | 비 |
|---|---:|---:|---:|
| bf16 median (2 clip) | 16.272–16.520 ms | **24.274–24.517 ms** | 1.484× |
| GFLOPs (profiler) | 782.2 | **1,119.9** | 1.432× |
| FLOPs 여유 (cutoff 7,053) | 9.02× | **6.30×** | |
| clip당 forward | 1 | 1 | |
| **시간 페널티 배수** | ×1.0 | **×1.0** | |

점수의 시간항은 `×(1 + (T−100)/200)`이다 (리뷰의 110 ms → ×1.05 예시와 일치).
**24.5 ms는 100 ms 임계의 4.08배 아래라 페널티가 붙지 않는다.** MR이 1.48배 느려진 것은
현재 점수 체계에서 비용이 0이다. FLOPs 여유도 9.02배에서 6.30배로 줄었을 뿐 cutoff와 멀다.

배포 확인:
- **raw B1 입출력 parity: 8/8 fixture 전부 bitwise 동일**, plan 차이 0.0 m, D3 차이 0.0.
  새 canvas tensor 2개도 검사 대상에 포함했다.
- **제출 경로**: 공식 test clip 12개로 `--mr-detail native` 빌드 통과. 모양 6×2, 전부 유한,
  cumsum 재적용 안 됨(재적용 시 끝점 3.53배), clip 간 상태 누수 0.0.

부수 발견 하나. native에서 motion 분기의 현재 canvas는 scene 분기가 이미 인코딩한 front
카메라와 **bitwise 같다**(실제 raw clip에서 확인). 즉 같은 이미지가 backbone을 두 번 지난다.
중복 pass를 제거한 변형도 재봤다: 1,058.9 GFLOPs(−5.4%)지만 시간은 24.364 ms로 **차이가
없다**(batch 1에서 GPU가 포화되지 않음). 이득이 없으므로 채택하지 않고, 등록된 것은
학습된 그대로의 그래프다.

## 4. 현재 돌고 있는 것 (§10.3, §10.4)

GPU 5·6에서 병렬 실행 중. 각 20,554 update, 약 6시간 예상.

| run | GPU | 목적 |
|---|---|---|
| **MR-NATIVE-s1** | 5 | seed 복제. 데이터 계약이 s0와 동일함을 확인(83,700행 / 310 scene / 동일 SHA) |
| **MR-W64-s0** | 6 | descriptor 32 → 64. 그 외 전부 MR-NATIVE와 동일 |

순서에 대해: §10은 3 → 4를 순번으로 적었지만 GPU가 비어 있어 **병렬로 띄웠다**. 두 실행은
서로 독립이고, 4단계의 게이트는 착수 조건이 아니라 해석 조건이다. 따라서 W64의 판정은
복제 결과가 유지되는 것을 전제로 읽는다 — 복제가 뒤집히면 원인을 먼저 본다.

### W64 사전 점검 (`w64_smoke.json`)

리뷰가 요구한 항목을 실제 모듈에서 측정했다.

- **재초기화 집합**: 정확히 4개 — `projections.0/1.weight`, `correlation_fuse.0.weight/bias`.
  나머지 tensor는 R0와 bitwise 일치. MR-NATIVE와의 step-zero parity는 **성립하지 않으며
  그렇게 기록했다**. +155,648 파라미터(+0.59%).
- **기존 32채널 tensor를 reshape하지 않았고, 추가 채널을 0으로 채우지도 않았다.** 양쪽을 0으로
  채우면 곱이 항등 0이 되어 gradient가 양쪽 모두 0이 된다. 새로 초기화해 그 경로를 피했다.
- **gradient 도달 확인**: 5 update 동안 세 tensor의 grad norm이 전부 양수. 기존 채널(0–31)
  이동량 2.5035e-4 대 신규 채널(32–63) 2.5034e-4 — 신규 용량이 실제로 학습된다.
- **점곱 정의는 cosine 그대로 유지**했다. bin은 [−1,1]에 머문다. 다만 무상관 feature에서
  전형적 크기가 1/√C로 줄어드는 것은 사실이고, 측정했다: abs_mean 비 **1.4223** 대 √2=1.4142.
  보정하지 않고 기록만 한다(정의를 바꾸지 않기 위해).
  그 shrink가 손실 스케일을 흔드는지도 봤다 — 뒤의 GroupNorm이 대부분 흡수해서
  `motion_features` std가 0.4886 → 0.5081(+4%)에 그친다. √2가 전달되지 않는다.
- optimizer 그룹은 head(5e-5)로 기존 32채널 tensor와 같다.

## 5. 남은 것

1. 두 학습 종료 → 같은 producer로 오차표 갱신, 복제 판정, W64 판정.
2. NATIVE seed0/seed1 50:50 weight average는 **평가만**(§8). BN buffer는 fixed 정책이라
   동일하면 보존, 다르면 자동 평균하지 않는다.
3. ADJ 또는 다른 단일 비교는 W64 결과를 보고 정한다. 자동으로 잇지 않는다.
4. H는 닫힌 채다. 열기 전에 후보·전처리·선택 기준 revision을 기록한다.
5. 제출 업로드는 파일·잔여 횟수·사용자 승인 확인 뒤에만 한다. 이번에 한 것은 12 clip
   smoke이고 공식 제출물이 아니다.

## 주장하지 않는 것

- native detail이 D3를 낮춘다 — 주 비교 CI가 0을 포함한다.
- 이번 이득이 새 분포에서 유지된다 — V0는 반복 사용된 개발 집합이고 arm마다 단일 seed다.
- 0.15 도달 경로가 보인다 — 이 결과에서 도출되지 않는다.
- radius 하나가 원인이다 / correlation이 물리적 운동을 복원했다 / 다른 병목이 없다 —
  전부 이번 대조가 답하지 않은 질문이다.
