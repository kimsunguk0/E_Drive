# 순수 선택 규칙 대 학습된 재순위 (2026-09-10)

## 질문

규정을 가장 엄격하게 읽으면 — planner 네트워크가 궤적 후보들을 내고, goal과
status는 **학습 없이 그중 하나를 고르기만** 한다 — 성능을 얼마나 잃는가.

## 사다리

같은 C 후보 집합(P20×V64 = 1,280개), 같은 TUNE 1,998행.

| 구성 | goal | status | tune D3 |
|---|---|---|---:|
| 같은 후보의 oracle | — | — | 0.071460 |
| **학습 MLP (37,697p)** | 입력 | 입력 | **0.138274** |
| 학습 MLP | 입력 | 0 | 0.236737 |
| **규칙: v0 + goal + base score 혼합 (최고)** | 규칙 | 규칙 | **0.253044** |
| 학습 MLP | 0 | 0 | 0.293245 |
| 네트워크 base score만 | 없음 | 없음 | 0.335924 |
| 규칙: v0로 속도만 | 없음 | 규칙 | 0.370695 |
| 규칙: goal cross-track으로 경로만 | 규칙 | 없음 | 0.688859 |

규칙 계열은 파라미터가 없거나(v0 최근접, goal cross-track 최근접) 결합
가중치 하나뿐이며, 학습하지 않는다. 가중치는 tune에서 스윕했으므로 그만큼은
유리하게 잡힌 값이다.

## 읽기

**엄격한 해석의 비용은 약 +0.115다.** 0.138274 → 0.253044. 0.15에 한참 못
미친다.

세부가 더 말해주는 것이 있다.

- **단순 매칭 규칙은 네트워크 점수보다도 나쁘다.** v0로 속도를 고르면
  0.370695로, 아무것도 안 쓴 0.335924보다 나쁘다. "현재 속도에 맞는 속도
  프로파일을 고른다"는 직관이 틀렸다는 뜻이다. 차는 가속·감속 중이고,
  현재 속도는 3초 프로파일을 정하지 못한다.
- 규칙이 쓸모 있어지는 것은 **네트워크 점수를 다시 섞을 때**뿐이다
  (0.253044). 즉 status·goal은 네트워크의 판단을 보정하는 역할이지 그
  자체로 후보를 지목하지 못한다.
- 학습된 head가 최고 규칙보다 0.115 낫다는 사실은, head가 status를
  **통과시키는 것이 아니라 점수 함수를 학습하고 있다**는 뜻이다. 성능에는
  좋지만, "선택일 뿐"이라는 방어에는 불리한 사실이다.

기여 분해도 나온다. 영상 토큰 + 후보 기하 + base score만으로 0.293245,
goal을 더하면 0.236737, status를 더하면 0.138274다. 즉 학습 구조에서
goal이 −0.056, status가 −0.099이다.

## 남는 선택지

1. **주최 측 질의.** 0.138과 0.253을 가르는 문제이고, primary CE(0.1305)도
   32→128→64→1 MLP가 status·goal을 먹는 **동일 구조**다. 셀렉터 라인
   전체가 이 답에 걸려 있다.
2. **2단계 구조.** goal·status 없이 학습한 head(0.293245)의 점수 위에 규칙을
   얹는 것. 여기 규칙은 base score 위에 얹어 0.253044였으므로 더 나은 점수
   위에서는 개선이 기대되지만 측정하지 않았다.
3. 규칙 설계를 더 다듬는 것. 다만 격차가 0.115라 다듬기로 메우기는 어렵다.
