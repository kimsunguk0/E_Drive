# base 학습량과 state_hat 조건 (2026-09-11)

## 1. base 학습량 — 큰 개선, 그리고 포화

| base | epoch | tune D3 | oracle | state vx MAE |
|---|---|---|---|---|
| C 원본 | 0.584 | 0.313933 | 0.164108 | 2.0738 |
| C 8k seed0 | 2.3 | 0.211782 | 0.135414 | 1.8226 |
| C 8k seed1 | 2.3 | 0.202737 | 0.132032 | 1.7849 |
| C 16k seed0 | 4.7 | 0.202137 | 0.129518 | 1.6413 |

**0.584 → 2.3에폭이 −0.102다.** 반면 **2.3 → 4.7에폭은 무의미하다** — 16k의
0.202137이 8k 두 시드(0.202737, 0.211782) 범위 안이다.

base 시드 분산을 처음 쟀다: 같은 조건 8k 두 시드가 **0.009** 차이다.
head 시드 분산 0.0008의 11배이므로, base 비교는 0.009를 잡음 바닥으로 읽는다.

## 3. state_hat 조건 — 실패

제공 status 대신 모델 자신의 영상 추론 상태를 공통 인지 query 조건으로 넣었다.
제공 데이터가 네트워크에 전혀 들어가지 않으므로 Q10 범위다.

| arm | 조건 입력 | tune D3 | oracle | state vx MAE |
|---|---|---|---|---|
| C 8k | 제공 causal | **0.211782** | 0.135414 | 1.8226 |
| B 8k | 없음 | 1.015915 | 0.909381 | 1.0680 |
| **state_hat** | 자기 추정 (미분리) | **1.047269** | 0.955800 | 2.1058 |
| **state_hat_detached** | 자기 추정 (detach) | **0.949753** | 0.858844 | **0.9770** |

**둘 다 status 없는 B(1.0159) 수준이다.** 즉 자기 추정을 되먹여도 아무것도
얻지 못한다.

detached 쪽이 state head vx MAE **0.9770**으로 전 arm 중 가장 좋은데도
D3는 0.9498이다. 지금까지 얻은 최선의 영상 속도 추정을 넣어도 소용이 없다.
앞서 잰 정확도 곡선과 일치한다 — MAE 0.4를 넘으면 status는 가치가 없고,
1.0 근처에서는 없느니만 못하다.

미분리 arm은 state head가 2.1058로 퇴화했다. planning 경사가 흐르니
state_hat이 상태 추정을 그만두고 임의의 4차원 잠재변수로 표류했다.

## 결론

제공 status를 규정 안에서 planner까지 나를 방법이 없고, 영상 추론으로
대체하는 방법도 현재 정확도에서는 없다. 남는 것은 status 없이 가는 것이며
그 값이 **0.200396**이다.

base 학습량 지렛대는 2.3에폭에서 소진됐다.
