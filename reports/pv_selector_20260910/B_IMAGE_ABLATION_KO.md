# B arm의 영상 교체 대조 (2026-09-10)

## 질문

B(네트워크에 status 전무)를 보험으로 쓰려면 먼저 **영상 기여 시험**을 통과해야
한다. 제안된 설계에서 영상이 하는 일은 경로 P20 선택 하나뿐이므로, 영상을
바꿨을 때 **경로가 무너지는지**가 관건이다.

## 방법

primary·C에 썼던 것과 동일한 donor 매핑(1,998행, donor scene 항상 다름).
`images`와 `history_images`만 교체하고 calibration·goal·행 식별자·GT는 그대로.
B 체크포인트 `temporal_b_history_s0_v1` (SHA `79fdd636…`), P20×V64.

전체 V1024 oracle은 유지된 P20 경로에 bank의 1,024개 속도를 전부 붙여
GT 최소 오차를 직접 계산했다(독립 계산).

## 결과

| 지표 | 원본 | 다른 장면 영상 | Δ |
|---|---:|---:|---:|
| base scorer D3 | 0.837174 | 5.090829 | +4.253655 |
| P20 × V64 oracle | 0.606489 | 4.838167 | +4.231678 |
| **P20 × 전체 V1024 oracle** | **0.069498** | **0.318604** | **+0.249106** |

원본의 두 oracle(0.606489, 0.069498)은 별도로 돌린 단계별 진단
(`B_AXIS_ORACLE_KO.md`)의 값과 정확히 일치한다. 계산 경로가 다른 두 방식이
같은 수를 냈다.

## 읽기

**B의 경로도 영상이 정한다.** 전체 속도를 붙인 oracle이 0.0695 → 0.3186으로
4.6배 나빠진다. status·goal·calibration을 전부 고정한 상태에서 영상만 바꾼
결과다.

C의 같은 시험이 oracle 0.071460 → 0.369642(+0.298182)였다. B의 경로 축은
+0.249106으로 **같은 규모**다. 즉 B도 영상 기여 시험을 통과한다.

따라서 "backbone에 status를 넣지 않고 최종 선택에서만 준다"는 설계는
규정 두 축을 모두 만족할 수 있다 — 네트워크에 과거 정보가 없고(판정 기준 1),
영상이 후보 집합을 실제로 만든다(실질 기여 시험).

## 남는 것

이것은 천장과 경계에 대한 결과다. 실현값은 아직 없다. B + status 선택기를
학습해야 하며, C 대비 핸디캡 셋(base score 특징 상실, 256-d 토큰 사용 불가,
B 자체 0.584에폭)은 그대로다.

교란은 영상을 지우는 것이 아니라 다른 장면 것으로 바꾸는 것이므로 순수한
인과 효과로 해석하지 않는다. TUNE은 반복 사용된 탐색 집합이다.
