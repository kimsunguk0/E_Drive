# A2 잔여 오차 진단 — 2026-09-20

새 학습 없이 저장 예측과 고정 checkpoint 개입을 검사했다. 결과의 핵심은 **일반 주행의 표본별 진행량 오차가 여전히 크고, FRESH는 기존 계보보다 일반화가 좋아진 대신 학습 데이터에서도 정지·출발·방향 출력을 덜 맞추고 있다**는 것이다. 가감속 타이밍 하나가 전체 오차의 원인이라고 결론 내릴 근거는 없다.

## 3. 가감속 타이밍만의 문제는 아니다

현재 acceleration 대신 **GT 미래 첫 2초의 네 구간 평균 속도**를 사용해 고정 진단 그룹을 만들었다. 네 구간의 최고−최저 속도 차이가 0.5m/s 이하이면 작은 변화 그룹이다. 이는 현재 vx/ax 측정값이나 배포 selector가 아니다.

|일반 주행 내 GT 미래 속도 변화|행 수|고정 평균 PREFIX|전체 점수 기여|
|---|---:|---:|---:|
|첫 2초 범위 ≤0.5m/s|1,306|0.140241|0.091669|
|범위 >0.5, 마지막−첫 속도 >0.5m/s|270|0.186744|0.025236|
|범위 >0.5, 마지막−첫 속도 <−0.5m/s|297|0.163563|0.024313|
|나머지 비단조 변화|2|0.214448|0.000215|

작은 변화 그룹은 전체 점수의 60.82%를 차지한다. 해당 그룹의 **첫 2초 기여만** 계산해도 0.067499로 전체 첫 2초 기여의 60.85%다. 가감속 구간은 행당 어렵지만, 큰 가감속 전환을 고치는 것만으로 전체 진행량 오차를 설명하거나 해소할 수 없다. 작은 가감속과 시점 오차까지 없다고 말하는 것은 아니다.

기하 구성요소를 GT로 교체한 진단도 진행량 문제와 일치한다.

|고정 평균의 기하 진단|PREFIX|
|---|---:|
|원래 출력|0.150724|
|GT 구간 길이 + 예측 구간 방향|0.057239|
|예측 구간 길이 + GT 구간 방향|0.119471|

GT 교체는 배포 불가능하고 PREFIX 최적화 oracle도 아니다. 어떤 구성요소의 오차가 큰지 보는 근거일 뿐, 길이를 영상에서 그만큼 예측할 수 있다는 증거가 아니다. GT 방향의 영길이에는 예측 방향, 예측 영길이에는 이전 예측 방향/고정 +x fallback을 사용했다.

전체 표본의 진행량 오차 부호는 상당히 상쇄된다. 예를 들어 고정 평균의 첫 0.5초 구간 속도형 오차는 signed mean +0.0171m/s, absolute mean 0.1056m/s다. 전역 상수나 동일 배율 보정보다 장면별 과대/과소 진행을 구분해야 하는 문제라는 근거다. 별도 배율 탐색은 실행하지 않았다.

## 4. 예측 상태 숫자를 더 정확히 만드는 것만으로는 부족하다

|예측 history 숫자만 0|0.164282|0.158694|
|예측 state/history 모두 0|0.164534|0.158538|

State/history 모두 제거했을 때 최종 계획 자체의 PREFIX 거리는 QREFINE 0.007767m, FRESH 0.001360m다. History 단독은 각각 0.000659m, 0.000179m다. 단순히 평가 점수에서 이득과 손해가 상쇄되는 것뿐 아니라 **계획의 실제 반응도 작다**.

반면 motion feature 제거는 각각 +0.070992, +0.044144 악화된다. 현재 checkpoint는 숫자 readout보다 연속 영상 운동 표현에 훨씬 민감하다. State/history supervision이 공유 표현 학습에 불필요하다는 뜻은 아니며, OFF로 재학습한 결과도 아니다. 큰 정확도 향상을 숫자 head의 MAE 감소만으로 기대할 근거는 약하다. 기존 QREFINE BOTH_OFF 평가를 재현했고 새 발견으로 중복 계산하지 않는다.

## 5. FRESH는 현재 정지를 알아보면서도 경로를 움직인다

V0 정지 유지 99행에서 FRESH의 현재 stop probability는 평균 0.9048이며 99행 모두 ≥0.5다. 그럼에도 평균 예측 이동 거리는 0.5초 0.0871m, 1초 0.1354m, 3초 0.2907m다. 대응 GT는 0.00137m, 0.00146m, 0.00521m다.

이는 해당 그룹에서 현재 정지 분류 실패만이 원인은 아니라는 직접 근거다. 다만 현재 stop=1이어도 앞으로 출발할 수 있으므로, stop logit 하나로 미래 궤적을 모두 0으로 만드는 근거는 아니다.

현재 정지→출발 24행에서도 FRESH는 23행을 현재 정지로 분류한다. 평균 0.5초 이동 거리는 예측 0.2685m, GT 0.0295m이고 3초에는 예측 2.6952m, GT 2.9189m다. 평균적으로 초기에 과하게 전진하고 뒤에는 진행량이 부족한 형태다. 모든 행의 정확한 출발 시점이 같다는 주장이나 하나의 시간 지연으로 해결된다는 결론은 아니다.

과거 P6의 stop 분류 가중치 조정은 두 초기 계보에서 일관된 계획 개선을 주지 못했다. 당시 데이터/모델은 달랐으나, 같은 BCE 비중 변경을 새로운 해결책처럼 반복할 근거는 없다 (`reports/p6_stop_balance_execution_20260908_ops.json`).

## 7. 다음 실행의 우선순위 — 이번에는 미실행

1. **FRESH의 수렴을 한 번 더 시험한다.** 새 모듈 없이 고정 terminal에서 낮은 LR continuation 6,852 update 한 번을 제안한다. 제안 시작값은 backbone 1e-6 / 기존 나머지 1e-5 / warmup 100 / cosine / 기존 batch·loss·BN·증강·입력 유지다. Fresh optimizer 여부와 sample stream은 착수 전 고정한다. 1,142 간격 평가, 주 비교 terminal−parent, best-on-V0는 별도 표시. 전체뿐 아니라 일반 주행, 첫 2초, 정지·출발, 횡방향을 함께 저장한다. 이것은 아직 채택·실행된 protocol이나 성능 보장이 아니다. 과거 오래 학습한 QREFINE의 G0와 질문이 다르다.
2. **서로 다른 초기화 계보의 보완성을 실제 제출 후보로 연결한다.** 현재 고정 평균 0.150724는 로컬 DEV 캐시 결과다. 이미 완료된 A2 FULL은 보존하되 이를 QREFINE FULL로 부르지 않는다. FRESH/QREFINE의 확정 레시피를 FULL로 옮길 때는 별도 계보로 만들고, 동일한 raw adapter의 두 모델 평균을 검증한다. 전체 forward FLOPs/4090 시간/clip isolation을 다시 측정한다. DEV 변화량을 서버 점수로 환산하지 않는다.

새 구조의 우선순위는 위 두 작업보다 낮다. 계속 학습해도 현재 stop 인지와 미래 계획의 괴리가 남는다면, 그때는 **현재 state head 강화 대신 시각 특징에서 미래 구간 진행을 직접 예측하는 출력 구조**를 별도 비교할 수 있다. 기존 LEN이나 실패한 pooled residual과 같은 실험으로 포장하지 않고, 같은 추가 학습 control을 둬야 한다. 현재 자료만으로 이 구조가 성공한다고 주장하거나 자동 실행하지 않는다.

이번에는 MH4/QREFINE/offset/command/보조 loss 비중 스윕, raw status 경로 확대, GT 조건별 모델 선택을 실행하지 않았다. 이전 C2F가 큰 이득을 못 줬다는 사실은 그 추가 모듈의 결과일 뿐 모든 영상 motion 개선의 불가능성을 뜻하지 않는다.

**서버 0.15는 확인되지 않았다.** 확인된 기존 MR FULL 서버 점수는 0.185968928이고, 이번 0.150724는 DEV 모델 두 개의 저장 예측 평균이다. 새 학습·FULL 이전·Docker 검증·제출은 이번 진단에 포함되지 않는다.
