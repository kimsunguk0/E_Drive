## 1. Q10-clean MotionDrive

A2 wrapper를 씌우지 않고 부모의 query 텐서 5개를 드롭해 로드한다
(26,426,936 대 26,428,184). 상태 오버레이가 없고 `provided_status5`를 구성하지
않는다. planner는 자기 `predicted_state`/`predicted_history`만 받으며 이는 Q10이
planner 입력으로 명시 허용한 값이다. goal은 scene feature 형성 단계에만 들어간다.

**현재 프로젝트에서 제공 정보가 네트워크 어디에도 없는 구성의 최선은 0.258544다.**

## 2. state head 병목은 loss도 BF16도 아니다

감사의 F2/F3를 그대로 수정했다. state projection을 autocast 밖 FP32로 옮기고,
state weight를 0.1 / 2.0 / 10.0으로 쓸었다. B arm(제공 status 없음), 8,000 step.

| state weight | FP32 | tune D3 | oracle | **vx MAE** | occ/lane |
|---|---|---|---|---|---|
| 0.1 (원본, BF16) | 아니오 | 1.015915 | 0.909381 | 1.0680 | 0.472/0.425 |
| 0.1 | 예 | 1.004079 | 0.903177 | 1.1105 | 0.468/0.422 |
| 2.0 | 예 | 0.972981 | 0.863932 | 1.0621 | 0.466/0.424 |
| 10.0 | 예 | 0.985920 | 0.888635 | **0.9852** | 0.472/0.424 |

**가중치를 100배 올려도 vx MAE는 1.11 → 0.99, 11% 개선에 그친다.** FP32 전환은
측정 가능한 변화가 없다(0.1에서 1.0680 → 1.1105로 오히려 조금 나쁜데, 시드
분산 안이다).

따라서 감사의 가설 — 작은 loss 기여와 BF16 반올림이 1 m/s 정체의 원인 — 은
**기각된다.** 원인은 표현이다. stride-16 특징의 공간 global mean과 과거 2프레임
구조가 자차 속도를 약 1 m/s보다 잘 추정하지 못한다.

정확도 곡선은 status가 의미를 가지려면 vx MAE 0.2 아래여야 한다고 말한다.
100배 가중치가 0.99를 주는 구조에서 0.2는 도달 거리 밖이다. **SDV2의 Q10
경로는 이제 올바른 축(추정기 자체)에서 닫혔다.** 조건 경로가 아니라 추정 능력이
막는다.
