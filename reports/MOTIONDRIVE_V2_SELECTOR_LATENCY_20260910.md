# 셀렉터 트랙 재검토와 3090 지연 실측 (2026-09-10)

09-09 P/V 스크린(1.509)만 보고 셀렉터 경로를 기각한 것은 성급했다. 과거 기록에
작동한 셀렉터가 있었고(PHASE_A: baseline 0.5389 → visual champion 0.3516 →
selector 0.2411 → +residual 0.2345), 그 계열이 중단된 이유는 정확도가 아니라
dense VAD trunk의 지연이었다(COMPLIANCE.md: 3090 586.6 ms, 페널티 ×3.43).

## 1. 지연 제약은 소멸했다

RTX 3090(`intern@192.168.10.182`, `adcl-latency-runtime:cu128`), batch 1,
CUDA events, warmup 20 + 반복 50.

| 구성 | median ms | p95 |
|---|---|---|
| 과거 216×384 (현재) | 32.90 | 32.96 |
| 과거 288×512 | 35.66 | 35.69 |
| 과거 324×576 | 37.62 | 37.68 |
| 과거 432×768 (전해상도) | 43.55 | 43.61 |
| 과거 432×768 + 현재 540×960 | 51.93 | 52.03 |

09-08 실측 P7 trained LAST6000은 38.69 ms였다(이 표는 랜덤 초기화라 절대값이
다르며, 구성 간 차분만 신뢰한다). §8 개발 목표 3090 median 80 ms 대비 **41%**,
공식 4090 100 ms 경계 대비 39%다. 과거 프레임을 전해상도로 올리는 비용은
**+10.7 ms**로 예산 안이다.

## 2. 셀렉터 재구성 결과 (tune1998, 단일 관측)

후보: K=1024 train203 뱅크(`p7_train203_bank_feasibility_20260908_ops`)에서
direct 예측 기준 prefix-nearest M12, 여기에 모델 자신의 예측을 13번째로 추가.
학습은 train203 전체, ego status는 어떤 형태로도 입력하지 않았다.

| 구성 | tune D3 | regret | direct(0.2806) 대비 |
|---|---|---|---|
| M12 (자기 예측 없음), 공유 latent | 0.2993 | 0.1314 | +0.019 |
| M13, 공유 latent 정상 | 0.2754 | 0.1203 | −0.005 |
| **M13, 공유 latent 0** | **0.2712** | 0.1161 | **−0.009** |
| M13, 후보별 경로 BEV 정상 | 0.2751 | 0.1201 | −0.006 |
| **M13, 후보별 경로 BEV 0** | **0.2723** | 0.1172 | **−0.008** |
| M13, 후보별 경로 BEV 셔플 | 0.2868 | 0.1317 | +0.006 |
| M13 shortlist 오라클 | 0.1551 | 0 | −0.126 |

관측 세 가지.

- **자기 예측을 후보에 넣는 것이 필수다.** 없으면 0.2993으로 direct보다 나쁘다.
- **시각 증거가 전이되지 않는다.** 공유 latent와 후보별 경로 BEV 두 방식 모두
  0으로 없앤 쪽이 더 좋다. 셔플이 정상보다 나쁘므로 스코어러가 그 feature를
  실제로 쓰고는 있으나, 학습 세션에만 맞는 방향으로 쓴다.
- **이기는 구성은 기하 feature만 쓰는 셀렉터이고 −0.008~−0.009다.** 세션
  부트스트랩 sd 0.040 안쪽이라 판별 불가다.

PHASE5EFG는 같은 음성 대조에서 시각 기여가 실재했다(정상 0.2612 / 셔플 0.2787 /
0 0.2814). 그쪽은 dev38/train330에 trunk도 다르므로 직접 비교하지 않는다.

### 세션 5-fold CV는 사용할 수 없다

train203 세션 단위 CV에서 regret 0.0254, selected 0.0994가 나왔으나 이는
**뱅크 누출**이다. 뱅크가 train203 전체 행의 medoid로 적합되어 held-out 세션의
궤적이 이미 후보에 들어 있다. shortlist 오라클이 train 0.0739 vs tune 0.1551인
것이 그 증거다. tune 값만 유효하다.

후보 안에 답이 있으나 고르지 못한다. 그리고 골라야 하는 축은 종방향 거리·타이밍
이며(PHASE_A: "끝점 맞고 첫 3초 timing/속도 틀림"), 그것은 오늘 네 가지 방법으로
확인된 이 데이터의 벽이다.

## 4. 부수 측정

- **occupancy 래스터 정합**: 0.5 s 간격 두 프레임의 occ 확률맵을 ±14셀로 상관.
  실제 변위 5.27 m 대비 측정 0.51 m, corr 0.139. scene feature 정합(0.34 m,
  corr −0.20)보다 낫지만 여전히 실패. 이는 "occ 전역 강체 정합"의 기각이며
  객체 인스턴스 추적의 기각이 아니다.
- **카메라 리그 좌우 대칭**: 미러 짝이 전부 존재한다(0↔0, 1↔2, 3↔3, 4↔5),
  최대 상대차 0.016~0.063. 엄밀 대칭은 아니나 증강으로는 충분하다.
- **라벨 좌우 편향**: `fut y@3s` 평균 −0.738(중앙값 −0.718), `goal y` 평균 −1.237.
  우측 편향이 실재하므로 **반전 TTA는 부적절**하다(원본과 반전의 평균이 편향을
  지운다). 학습 증강은 추론이 원본이므로 이 문제가 없다.
